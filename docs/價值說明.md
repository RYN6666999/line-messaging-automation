## 一、這個需求原本有多痛

我需要把同一則活動問卷，依序發給 LINE 上 **4932 位**好友。用人工做的話，每一位都要：

```
開對話 → 等載入 →（太久沒聊會先冒出一個綠色確認筐，要點掉）→
點輸入框 → 貼上 → Enter 送出 → 切到下一位
```

把它換算成可量化的成本：

| 假設每位花費 | 4932 位總計 | 伴隨的失敗模式 |
|---|---|---|
| 10 秒 | ≈ 13.7 小時 | 純機械重複，容易漏發／重複送 |
| 20 秒（含等待與確認筐） | ≈ 27.4 小時 | 連發觸發 LINE 限流、可能點錯人 |
| 一次手滑 | 重複送給同一人 → 對方收到一整串 | 這個坑在開發中實際踩到 |

更大的問題在門檻：我**沒有資工背景，程式是從零開始**。走「先學程式再寫自動化」的路徑要花數週到數月；這不是耐心的問題，而是門檻問題。

---

## 二、我交付了什麼

- **兩件式架構**：`auto_click.py`（執行自動化）與 `mouse_position.py`（對齊工具）職責分離，互不干擾。
- **安全優先**：測試模式（`DRY_RUN`，只移動不點不送）、緊急停止（ESC／滑鼠甩到左上角）、嚴格的前景確認、可選的追蹤記錄。
- **讓非工程師能自己跑**：`.command` 雙擊啟動檔、套件自動安裝、權限指引、集中式設定區。
- **技術**：`pyautogui`（滑鼠／鍵盤）、`pynput`（鍵盤偵測）、`tkinter`（介面）。完整安裝與執行方式見 `docs/SETUP.md`。

## 三、這趟過程裡，我怎麼思考與動手

這才是這份 repo 真正想呈現的部分 — 物件是 LINE 自動化，但你在過程中能看到的是：

**1. 敢質疑，並要求證據。**
開發到一半，點擊突然失效。最關鍵的線索是我自己提出的：「是不是你加的標記視窗擋住了點擊？」我沒有照單全收，而是回頭用追蹤資料驗證，最後接受並修正。會用 AI 不只是會下指令，而是敢對 AI 的產出說「不對」，並要求它拿出證據。

**2. 用資料下結論，不用感覺。**
每個「我猜是……」我都補一句「我查給你看」：多個 Python 干擾 → 逐一確認能否 import；前景檢查成本 → 真的量秒數；貼上失敗 → 讀到錯誤碼才下結論。先查證是我的整個流程的地基。

**3. 拆解勝過堆疊。**
卡了很多輪之後，最終最乾淨的解法不是寫更多程式，而是把「對齊標記」與「點擊執行」拆成兩支獨立工具 — 從根本消除「拖動視窗就壞」的問題。

**4. 有風險意識，不硬幹。**
不讓第一輪就送出真訊息；提醒 LINE 限流與帳號風險；每次放量前先小量驗證。「會解決問題」也包括「知道什麼時候不要硬來」。

**5. 把複雜交還給人類語言。**
整趟下來我一行程式都不用看懂 — 我用一句話描述目標、描述我看到的现象，AI 把它變成工具。這是「人類意圖 × AI 實作」的分工。
